# AGENTS.md

This file provides guidance for AI coding agents working on the Ancela project.

## Project Overview

Ancela is an experimental, **single-owner** AI assistant that users interact with over
SMS. It connects to real-world services (calendar, email, contacts, budget, the web) and
adds limited autonomy (reminders, standing rules, scheduled tasks). It's built with:

- **.NET 10** with C# 13
- **Aspire** for cloud-native orchestration and Bicep infrastructure-as-code
- **Azure Functions** (isolated worker model, v4)
- **Azure Cosmos DB** for data storage
- **Azure Service Bus** for the message queues
- **Semantic Kernel** for AI/LLM orchestration
- **OpenAI (`gpt-5.4`)** for the conversational model
- **Twilio** for SMS, **Microsoft Graph** (calendar/email/contacts), **YNAB** (budget),
  **Tavily** (web search), and **reMarkable** (owner-only document upload)

See `README.md` for the product overview, security/trust model, and setup. This file
focuses on internals for working in the code.

## Project Structure

```
Ancela/
├── Ancela.AppHost/          # Aspire orchestration & infrastructure (defines all Azure resources)
├── Ancela.FunctionApp/      # Azure Functions: HTTP triggers + Service Bus queue processors

├── Ancela.McpServer/        # Local stdio MCP server exposing read-only Ancela data to Claude Desktop
├── Ancela.ServiceDefaults/  # Shared service configuration (telemetry, health, resilience)
└── Ancela.slnx              # Solution file
```

## Build & Run Commands

```bash
# Build the solution
dotnet build

# Run locally with Aspire (launches all services + dashboard)
dotnet run --project Ancela.AppHost

# Run tests
dotnet test

# Deploy to Azure (see README for the first deploy). Docker must be running, and
# ANCELA_RESOURCE_PREFIX set. Never add --clear-cache to a routine deploy: see below.
aspire deploy --non-interactive --project Ancela.AppHost/Ancela.AppHost.csproj
```

## Code Style & Conventions

- Use **file-scoped namespaces**
- Use **primary constructors** for dependency injection
- Use **raw string literals** (`"""`) for multi-line strings
- Prefer **async/await** patterns throughout
- Use **nullable reference types** (enabled project-wide)
- Follow standard C# naming conventions (PascalCase for public members, _camelCase for private fields)
- Use **4 spaces for indentation** (enforced via .editorconfig)
- If an interface has a single implementation, include the interface definition at the top of the implementation file.

## Key Components

### Ancela.AppHost
- `AppHost.cs` - Aspire distributed application builder; defines storage, Service Bus queues (`chat-messages`, `reminders`, `standing-rules`, `scheduled-tasks`), Cosmos, OpenAI, and the Functions project, wiring secrets/env vars.
- `FixedNameInfrastructureResolver.cs` - Custom deterministic naming for Azure resources (uses `ANCELA_RESOURCE_PREFIX`).
- `aspire-output/` - Generated Bicep templates (regenerated by `aspire publish`).

### Ancela.FunctionApp
- `Program.cs` - Function app startup and DI (registers the Service Bus client and the agent module).
- `IncomingSms.cs` - HTTP trigger for Twilio webhooks; enqueues the message to the `chat-messages` Service Bus queue.
- `IncomingMessage.cs` - HTTP trigger for testing (non-Twilio); also enqueues to `chat-messages`.
- `ChatQueueProcessor.cs` - `ServiceBusTrigger` on `chat-messages`; routes to `ChatInterceptor`. Messages are handled one at a time (`maxConcurrentCalls: 1` in `host.json`, with `MaxReplicas = 1`): a message is saved to history only after it is answered, so one handled alongside another can't see it — a phone that sent a link as its own text got two blind replies. `MessageOrderingTests` pins the setting. On `ModelOutOfFundsException` it answers the sender and completes the message instead of retrying into the dead-letter queue.
- `ReminderQueueProcessor.cs` / `StandingRuleQueueProcessor.cs` / `ScheduledTaskQueueProcessor.cs` - `ServiceBusTrigger` processors that run the due reminder / autonomous evaluation / scheduled task.

### Ancela.Agent
- `Agent.cs` - Core orchestration: builds a kernel per request via `IKernelFactory`, advertises the profile-allowed functions to the model, and runs `Chat`, `Onboard`, `EvaluateStandingRule`, and `PerformScheduledTask`.
- `ChatInterceptor.cs` - Handles session/access commands before the model sees them: `hello ancela`, `goodbye ancela`, and owner-only `invite`/`revoke` (with required TOTP step-up). Invite-only registration.
- `AuditFilter.cs` - `IFunctionInvocationFilter` that audit-logs every kernel function invocation.
- `AutonomousToolGuardFilter.cs` - `IFunctionInvocationFilter` that hard-denies any function call outside the profile's allow-list (and owner-only functions for non-owners), as defense-in-depth. It also enforces the one restriction that applies in Chat: once a message has read email, calendar or the web (`UntrustedContentLog` in `kernel.Data["untrustedContent"]`), sending and instructions are switched off for the rest of that message. The denial tells the model to ask the user to confirm, and `Agent` adds a note to that reply in history so the confirming message sends without reading again — without the note it re-reads the email to check, and the send is switched off again.
- `DependencyModule.cs` - Service registration for the agent module.

#### Services (`Services/` folder)
- `UserService.cs` - User profiles / access state in Cosmos (replaces the old session service).
- `HistoryService.cs` - Per-user conversation history in Cosmos.
- `OwnerService.cs` - Identifies the owner (by `OWNER_PHONE_NUMBER`).
- `TotpService.cs` - RFC 6238 owner step-up verification (`OWNER_TOTP_SECRET`).
- `SmsService.cs` - Twilio SMS integration.
- `MediaService.cs` - Handling of inbound MMS media.
- `AuditService.cs` - Cosmos-backed audit log (`IAuditLog` / `CosmosAuditLog`).
- `ModelAvailability.cs` - Out-of-credit circuit breaker (in-memory; the app runs at `maxReplicas 1`). Open, model calls short-circuit with `ModelOutOfFundsException` and one call is let through every 5 minutes to detect a top-up. Also holds `OutOfFundsMessages`, the reply copy.
- `CreditAlertService.cs` - Texts the owner once per outage when OpenAI reports an empty balance (`insufficient_quota`). Classifies the exception; needs only Twilio, so it works when the model does not.
- `CreditAwareChatCompletionService.cs` - `IChatCompletionService` decorator that trips and reads the breaker. The single chokepoint: `Agent` is the only consumer, so chat, onboarding, standing rules and scheduled tasks are all covered here.

#### Semantic Kernel (`SemanticKernel/` folder)
- `KernelFactory.cs` - Builds a fresh `Kernel` per request for a given `KernelProfile` (`Chat`, `Onboarding`, `StandingRule`, `ScheduledTask`), loads plugins, and attaches the invocation filters. Onboarding loads only `RegistrationPlugin`.
- `KernelProfilePolicy.cs` - **Single source of truth** for which functions each profile may use. Autonomous profiles (`StandingRule`, `ScheduledTask`) are default-deny allow-lists; `Chat`/`Onboarding` are unrestricted. Also defines owner-only functions (`send_sms`, `send_email`, `create_calendar_event`, `send_to_remarkable`, `save_email_to_onedrive`, the Google Health reads, and the diagnostics self-check `check_services`/`check_anomalies`). Consumed both when advertising functions to the model and by `AutonomousToolGuardFilter`. Also holds the untrusted-content rules: which reads carry outside text (`get_recent_emails`, `get_calendar_events`, `web_search`, `web_fetch`) and what each switches off (`send_email`, `send_sms`, `remember_instruction`, `forget_instruction`; plus `web_fetch` after mail or calendar, but not after a search).

#### Plugins (`SemanticKernel/Plugins/` folder)
Each plugin pairs a `*Plugin` class (kernel functions) with a client/store/service for I/O.
- `MemoryPlugin/` - To-dos and knowledge (shared memory) in Cosmos. `get_todos` shows links as `(link)` unless `includeLinks` is set: a to-do keeps the whole link, but listing a ~600-character event link made every "what's on my list?" several texts longer (and `SmsService` cuts a reply off at 1600 characters).
- `ProjectsPlugin/` - Projects: longer-lived workspaces with notes and categorized entries.
- `GraphPlugin/` - Microsoft Graph: calendar, email, contacts, and `save_email_to_onedrive` (owner-only). `get_recent_emails` returns at most the 50 newest emails — in a busy inbox only a day or two — so its optional `search` (Graph `$search`: sender, subject, body) is how the model finds a particular email; it covers the whole folder. There is deliberately no date window: the 50 cap is always the tighter limit, so a window could only hide emails (the model passed one unasked), and each result carries its date. Graph rejects `$filter`/`$orderby` alongside `$search` (400) and returns matches newest first. That tool puts the raw message (.eml) in one OneDrive folder, has Graph convert it (`?format=pdf`), saves the PDF beside it and deletes the .eml; over Graph's 2 MB conversion limit it renders the headers and body alone (`EmailPdf`). **The app holds `Files.SelectedOperations.Selected` plus a write grant on that one folder, not tenant-wide file access** — `GRAPH_ONEDRIVE_DRIVE_ID` / `GRAPH_ONEDRIVE_FOLDER_ID` must name the granted folder, and anywhere else is a 403. File names come from email subjects, which the sender controls: `GraphClient` escapes the upload path itself because the SDK's `ItemWithPath` doesn't.
- `InstructionsPlugin/` - `remember_instruction` / `forget_instruction`: per-user instructions for how Ancela behaves with that user (a persona, what to call them, a lasting preference). Saved on the user's profile in `users` and listed in the Chat prompt's Current context on every message (`Agent.BuildInstructionsContext`), after history so the cached prefix is unchanged. Capped at 10 × 300 characters; line breaks are collapsed so one can't start a bullet that reads like a rule. Chat only: not in either autonomous allow-list, and switched off after an untrusted read, because a planted instruction would outlive the message that read it.
- `YnabPlugin/` - YNAB budget/account/transaction reads. `YnabClient` gets the plan ID from the plan list and looks names up through the accounts/categories/payees endpoints. Don't use the extension package's `GetPlanDetailAsync`: the plan detail is a full export (10.5 MB on 2026-10-19), and fetching it before every call made a cold call take 11-12 s, so the self-check's 8 s YNAB probe always timed out.
- `WebPlugin/` - `web_search` (Tavily) and `web_fetch`. `web_fetch` throws when Tavily can't read a page, which it reports with a 200 and the reason under `failed_results`; it used to return "", so a failed fetch looked like a page with no text.
- `WeatherPlugin/` - `get_forecast`: today's labelled daytime high and nighttime low from the National Weather Service (api.weather.gov; free, no key, US only). Place names resolve through Open-Meteo's geocoder first because NWS takes coordinates only. Exists because reading a high out of `web_search` snippets does not work — an unlabelled "63° 37°" got reported as a 35°F high on 2026-10-11. **NWS returns 403 without an identifying `User-Agent`.** Allowed in both autonomous profiles; unlike `web_fetch` it reads one fixed API rather than a model-chosen URL.
- `SmsPlugin/` - `send_sms` (owner-only).
- `ReminderPlugin/` - One-time SMS reminders (store + scheduler).
- `StandingRulePlugin/` - Recurring conditions evaluated on a timer (store + scheduler).
- `ScheduledTaskPlugin/` - Recurring actions on a clock schedule (store + scheduler).
- `RegistrationPlugin/` - User onboarding (`register_user`).
- `RemarkablePlugin/` - `send_to_remarkable` (owner-only); renders text to PDF with QuestPDF and uploads via `Remarkable.Api.Client`. Requires `REMARKABLE_DEVICE_TOKEN` (obtained one-time via `rmpair`).
- `DiagnosticsPlugin/` - Owner-only, on-demand self-check ("how are you?"): `check_services` probes every external dependency (Cosmos, Service Bus dead-letter queues, Twilio, Graph, the OneDrive folder grant, YNAB, Tavily, Google Health, reMarkable); `check_anomalies` scans the audit container and applies deterministic thresholds (`AnomalyEvaluator`) for unknown senders, failed TOTP step-ups, guard denials, high search/SMS/email volume, and tool errors.

### Ancela.Cli
Read-only Spectre.Console TUI for auditing the deployed Cosmos data and minting the owner TOTP secret. Commands: `ping`, `list`, `show` (browse containers), and `enroll` (generate `OWNER_TOTP_SECRET` + QR).

### Ancela.McpServer
A local stdio MCP server (`ancela-mcp`) that lets Claude Desktop read Ancela's data. Reuses
`IMemoryClient` from `Ancela.Agent`, authenticating to Cosmos with `DefaultAzureCredential`
(the same `az login` chain as the CLI).

- `Program.cs` - Host startup. **All logging goes to stderr** — stdout is the JSON-RPC channel and
  the default console logger would corrupt every response.
- `MemoryTools.cs` - The tools: `get_todos` and `get_knowledge`, both read-only. Returns `TodoView`
  / `KnowledgeView` projections that drop the soft-delete marker and, for knowledge, the
  contributor's phone number.
- `AncelaEnvironment.cs` - Config from environment variables (`ANCELA_COSMOS_ENDPOINT` or
  `ANCELA_RESOURCE_PREFIX`, plus `ANCELA_AGENT_PHONE_NUMBER` — the Cosmos partition key), because
  Claude Desktop launches the server as a bare subprocess.

**This is a second door into the data.** It queries Cosmos directly, so it does *not* inherit
`KernelProfilePolicy` or `AutonomousToolGuardFilter`, which only govern calls routed through the
kernel. Keep the tool set narrow and justified on its own terms; `McpToolSurfaceTests` pins it.

Install (re-run after changing the server):
```bash
dotnet publish Ancela.McpServer -c Release -o ~/.ancela/mcp
```
Then register it in `~/Library/Application Support/Claude/claude_desktop_config.json` under
`mcpServers`, pointing `command` at `~/.ancela/mcp/ancela-mcp` and setting `env` with
`ANCELA_COSMOS_ENDPOINT`, `ANCELA_AGENT_PHONE_NUMBER`, and a `PATH` that includes
`/opt/homebrew/bin` — a GUI-launched process does not inherit the shell PATH, and
`DefaultAzureCredential` shells out to `az`. Restart Claude Desktop to pick up changes.

## Configuration

### Local Development
User secrets are set in `Ancela.AppHost` (see README for the full list), e.g.:
```bash
dotnet user-secrets set Parameters:openai-api-key      "..."
dotnet user-secrets set Parameters:twilio-account-sid  "..."
dotnet user-secrets set Parameters:graph-client-secret "..."
dotnet user-secrets set Parameters:ynab-access-token   "..."   # optional
```
Owner step-up uses `OWNER_TOTP_SECRET` (from `ancela enroll`); resource naming uses the
`ANCELA_RESOURCE_PREFIX` / `ANCELA_RESOURCE_GROUP` environment variables.

### Azure Deployment
- The first `aspire deploy` asks for the subscription, resource group, location and secrets,
  and caches the answers in `~/.aspire/deployments/`; later deploys reuse them, so use
  `--non-interactive`. `--clear-cache` throws the cached resource group away too, and a
  different answer to that prompt targets something other than the live deployment.
- The image is built locally: a deploy that fails within seconds with "Docker is not
  running" has sent nothing to Azure. Start Docker and rerun.
- Cosmos DB uses role-based access; run `./configure_cosmos.sh` post-deployment to grant the
  role and create the database + containers.

## Cosmos DB Data Model

Single database (`anceladb`). All containers partition on `/agentPhoneNumber` (one value per
instance):
- **users** - User profiles, access state, and saved instructions
- **todos** - To-do items (shared)
- **knowledge** - Knowledge entries (shared)
- **projects** - Projects and their entries (shared)
- **history** - Conversation history (per-user; filtered by `userPhoneNumber`)
- **reminders** - One-time reminders (per-user)
- **standing_rules** - Standing rules (per-user)
- **scheduled_tasks** - Scheduled tasks (per-user)
- **audit** - Audit log of function invocations and session events

## Important Patterns

### Semantic Kernel Integration
- `IKernelFactory.Create(profile)` builds a fresh `Kernel` per request with its own `Kernel.Data` (per-request `agentPhoneNumber` / `userPhoneNumber`), so identity is never shared across concurrent invocations.
- The model only ever sees the functions allowed by `KernelProfilePolicy` for the active profile (and, for non-owners, with owner-only functions removed) — advertised via `FunctionChoiceBehavior.Auto(functions:)`.
- Three `IFunctionInvocationFilter`s run on every kernel, outermost first: `AuditFilter` (logging), `AutonomousToolGuardFilter` (hard-deny backstop matching the same policy) and `EmptyResultFilter` (below). They are registered in DI, and `new Kernel(_sp, plugins)` attaches them itself; adding them to `FunctionInvocationFilters` as well runs each twice (until 2026-10, every audit entry was written twice).
- Context is passed via `kernel.Data[]`.
- **A tool tells a failure apart from finding nothing, and Ancela never reports one as the other.** A failure throws; never catch it and return an empty result (Semantic Kernel gives the model "Error: …"). A lookup that finds nothing returns null or an empty list, not a record of nulls or zeros. `EmptyResultFilter` then replaces a null, blank or empty result with an explicit "worked and found nothing; not an error". On 2026-10-20 a sleep summary of all-null fields, for a night the watch hadn't synced, was reported as "Google Health still appears disconnected". Watch for APIs that answer 200 for a failure (Tavily's `/extract` puts it under `failed_results`), and ones that leave out a day with nothing recorded (Google Health returns no roll-up point; a point with an omitted value is a real zero).

### Session & Message Flow
1. Twilio webhook → `IncomingSms` enqueues to the `chat-messages` Service Bus queue and returns immediately.
2. `ChatQueueProcessor` dequeues → `ChatInterceptor`:
   - `hello ancela` → registers the owner, or onboards an already-invited user (others are silently dropped — invite-only).
   - owner `invite <number> <totp>` / `revoke <number> <totp>` → access management, gated by required TOTP step-up (fail-closed).
   - `goodbye ancela` → removes the account.
   - anything else → `Agent.Chat` (or `Agent.Onboard` if the profile is pending a name).
3. Autonomous work runs from the reminder / standing-rule / scheduled-task Service Bus queues via their processors, using the restricted kernel profiles.

## Testing Guidelines

- Use xUnit. Mock external services (Cosmos, Twilio, OpenAI/Graph/YNAB) — see `AgentTestBase`.
- Security-relevant behavior (profile allow-lists, owner-only gating, TOTP) has dedicated tests (`SecurityTests`, `TotpServiceTests`, `ChatInterceptorTests`) — keep them passing when touching those paths.

## Common Tasks

### Adding a New Semantic Kernel Plugin
1. Create a folder under `Ancela.Agent/SemanticKernel/Plugins/` with a `*Plugin` class (`[KernelFunction]` + `[Description]`) and a client/store for I/O.
2. Register the plugin and its client/store in `DependencyModule.cs`.
3. Inject the plugin into `KernelFactory` and add it to the relevant profile branch(es) in `Create`.
4. If any function should be callable by autonomous profiles, add it to the appropriate allow-list in `KernelProfilePolicy`; if it sends/mutates owner data, add it to `OwnerOnlyFunctions`.
5. Update the system prompt in `Agent.cs` if needed, and add tests.

### Adding a Capability to an Existing Plugin
1. Add a `[KernelFunction]` method to the plugin class.
2. Update `KernelProfilePolicy` if it needs autonomous or owner-only treatment.
3. Update the system prompt in `Agent.cs` if needed, and add tests in `Ancela.Agent.Tests/`.

### Modifying Infrastructure
1. Update `AppHost.cs` with new resources/references.
2. Re-run `dotnet run --project Ancela.AppHost` locally; `aspire publish` regenerates the Bicep in `aspire-output/`.
3. Deploy with `aspire deploy`.
